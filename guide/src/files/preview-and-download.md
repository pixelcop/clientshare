# Preview and download files

**Who:** People with view permission for the file or folder, including recipients
of **View & download** or **View, download & upload** links.

## Preview a document

1. Open the client workspace and find the file.
2. Select the filename or choose **Preview** from its actions.
3. Use the viewer's available controls to inspect the document.
4. Return to the file list when finished.

Preview behavior depends on the file type and browser. The app has viewers for PDFs, images, text, and audio; a file without a supported preview can be downloaded and opened in an appropriate application.

## Download a file

Use the row's download icon, or open **More** (three dots) and select **Download**.
Row icons appear when you hover or focus a row, and on touch devices. On narrow
screens, use **More** for actions that are not shown alongside the filename.

Your browser saves the file according to its download settings. Check its downloads list if you do not see the file immediately.

## Download a folder as ZIP

Use **Download ZIP** from the folder's **More** menu, or its download icon where
shown. Open the downloaded ZIP on your device to access its contents. Large folders may take longer to prepare.

## When a preview or download is unavailable

- **Uploads only:** the link does not allow reading or downloading documents. Ask the sender for read access if needed.
- **Unsupported preview:** download the file and open it locally.
- **Missing file or access error:** return to the workspace and refresh; the file may have been removed or your access may have changed.
- **Expired link:** ask the sender for a replacement link.

Downloading creates a copy on your device. Later changes to the portal document or link do not update or remove that copy.

## Discuss a file

On wide screens, files open with the conversation beside the preview. Select
**Comments** to hide or restore it when you need more document space. On narrow
screens, comments start closed; the same button switches between the conversation
and the document. The button shows a count and uses color when there are comments you can
read. Counts exclude removed comments and team notes you are not allowed to see.
Select **Add comment** below the conversation to open the editor. **Cancel** closes
it without discarding your draft. Closing the panel also keeps your draft while you remain
on that file.

- **Shared comments** are visible to signed-in people who can read the file,
  including people subsequently given access. Reading permission also allows
  these signed-in readers to comment; it does not allow them to edit the file.
- **Team-only notes** are visible only to staff who can read that file. Staff
  drafts start with **Team-only note** checked; uncheck it to post a shared
  comment. The checkbox title explains who can read the note.

Comments support simple Markdown: emphasis, lists, links, quotes, and code.
The rich-text editor formats Markdown as you type: for example, `**bold**`,
`*italic*`, and `- ` for a list. You can also paste Markdown. Selected mentions
appear as inline tags while editing. There is no separate preview step.
Comments are still saved as Markdown, not HTML. Reopening a comment restores its
formatting and mentions; editing may normalize Markdown spacing and delimiters.
Copy/paste uses Markdown or plain text rather than arbitrary HTML.
Raw HTML is not rendered; images appear as alt text.

Type `@` to open the mention dropdown, then type a name to narrow the suggestions.
Use the arrow keys and Enter, or select a name. Suggestions include only people
available to you who can read the file and the chosen audience; team notes
suggest staff only. Mentions do not grant access or send notifications.
- Comments store Markdown source, up to 4,000 characters. They belong to the file, not
  to a PDF page, annotation, or folder.
- Anonymous secure-link sessions cannot view or post comments. Sign in through
  your own account with file access to join the conversation.

Use a comment's **…** menu to edit or remove your own comments or view their
history. An edit cannot change the audience;
post a new comment if you need a different audience. Removed comments leave a
placeholder in the conversation. **History** lets you review your own earlier
versions, including removed text, while you still have the required access.
Other readers cannot browse your revision history.

Comments do not send email notifications or create activity-feed notifications.
Reopen the file to see new messages. Leaving the file discards an unsent
draft. If access is removed or expires, the conversation and its history become
unavailable to that person.
