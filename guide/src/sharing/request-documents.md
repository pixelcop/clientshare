# Request documents from a client

Use a **document request** when you need specific files and want to review each
item. For a one-off upload without a checklist, use an [Upload only link](#send-an-upload-link).

## Create a checklist

1. As an administrator or manager with access to manage the client, open the
   workspace root and choose **Document requests**. On mobile, look in the
   **Upload** menu.
2. Choose **New request**, give it a title, and add the documents you need. Add
   instructions where they help the recipient pick the right file.
3. The **Destination folder** defaults to the request title. Choose **Edit**
   beside the name if you want a different folder.
4. **Email all client users** is checked by default. Each client user with
   workspace access gets a separate email. Uncheck it to add specific client
   users, or leave the list empty to **Copy request link** and share it yourself.
   If outbound email is disabled, use the copy option instead.

The recipient can open the checklist without a portal account. They can add one
or more files to an item and return with the same link later. Signed-in users
see their usual portal navigation. Uploads are saved in the destination folder
under the client workspace as soon as they finish. **Submit for
review** tells the team that an item is ready. Adding files alone does not
submit the item.

Anyone with the link can see the named checklist, filenames attached to the
current submissions, and instructions or replacement reasons. The link does not
let them download files or browse the workspace. It expires after 30 days; staff
can revoke it sooner from the request.

## Review the documents

Open the request and use **Refresh** to check for submissions. Open a filename
to preview it. On desktop the request checklist stays to the left of the file
and file comments open on the right. On a smaller screen, use **Request** in the
file toolbar to switch files, review the current item, or return to the full
checklist.

For each submitted item, choose **Accept** or **Ask for replacement**.
A replacement reason is visible to the recipient. Send them the
same link so they can submit a correction; the other items keep their status.
Staff can see earlier review decisions under **Review history**.

The checklist is complete when all items are accepted. Revoking the link does
not delete files already received in the workspace.

## Collect files without a checklist

**Who:** People with upload and create-sharing-links permissions in the client or folder.

Use an **Upload only** secure link when you want a recipient to send documents without downloading material from the workspace.

## Prepare the request

1. Open or [create the client workspace](../clients/manage-clients.md).
2. Organize any destination folders you need.
3. List the documents you want in your message, using names the recipient will recognize.

For example, ask for a project brief, an asset inventory, and supporting images.
Explain your deadline. Upload-only recipients cannot browse existing folders;
create a link to the destination folder rather than asking them to find it.

## Send an upload link

1. Open **Share workspace** at the client workspace root for the entire client,
   or **Share folder** in the destination folder. Select **Sharing links**.
   On mobile, use the **Upload** menu to find the sharing action.
2. In **Create a link**, select **Upload only**.
3. Set the expiry to cover the requested submission period.
4. Create the link, then use **Copy link** or **Email link** to send it. Check the email status if sending from the portal.

You can include the [recipient instructions](../for-clients/send-and-receive-documents.md) in your message.

## What the recipient sees

The recipient can use **Upload**, choose **Upload folder** from its menu, or drag
files onto the page. They do not need an account and cannot see existing files or folders.

## Confirm receipt

Open the client workspace and check that the requested files are present. Review available **Activity** notifications and inspect the documents as needed. If something is missing, follow up with the recipient using your usual communication channel.

This workflow uses secure links and the file list; it does not create a separate checklist with per-document request statuses. Keep your request list in your message or your team's existing task system.

When collection is finished, [revoke the link](./manage-links.md) if it is no longer needed.
