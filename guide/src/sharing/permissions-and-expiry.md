# Choose link permissions and expiry

**Who:** People creating links or interpreting their access.

## Choose an access type

| Link option | Recipient label | Allows | Typical use |
| --- | --- | --- | --- |
| **View & download** | Read-only | View and download | Deliver completed documents |
| **Upload only** | Upload-only | Upload; downloads are disabled | Collect supporting documents |
| **View, download & upload** | Read & upload | View, download, and upload | Exchange drafts and responses |

Links never allow deletion or management of other people's access. **Upload only**
hides existing files and folders. Uploaded files do not replace existing files.

Read-only recipients can browse folders, preview files, download files, and download folders as ZIP archives. They cannot upload or replace files, create folders, or delete anything.

Some whole-client **View, download & upload** links offer account creation.
For account access to a shared file or folder, ask the sender for an email invitation.

## Understand the scope

A link shares an entire **client workspace**, a **folder and everything inside**,
or a **single file**. A folder link does not open other folders outside it. File
links allow viewing and downloading only. Check the name before creating the link.

Someone with an account may also have access separately. Changing a link does not
change their account permissions.

## Set an expiry

In **Sharing links**, open **Link expiry** and choose **Expires in 7 days**,
**Expires in 30 days**, or **Custom date…**. A custom date ends at the end of the
selected day in your local timezone; select **Set expiry** to confirm. Hover over
the control or open its menu for the exact date and time. Links cannot use **No expiry**.

In the separate **Client-wide links → New link** form, **Expires in (days)** accepts
a suggested number of days or a whole number from **1 to 120**. Check the displayed
expiry before sharing. The link stops working after expiry, even if someone already has it open.

**Send documents** and **Collect uploads** select a starting set of permissions.
Check the permissions and expiry for each new recipient.

## Expiry versus revocation

- **Expiry** ends access at the scheduled time.
- **Revoke** ends the link's access when you no longer want it used.

To change an existing link's permissions or provide more time, create a replacement with the intended settings and revoke the old one if it is still active. The link list has no edit action.

Neither expiry nor revocation removes copies already downloaded. See [Review and revoke links](./manage-links.md).
